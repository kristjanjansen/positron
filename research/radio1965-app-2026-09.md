# radio1965 — how Tarmo's app actually works (2026-09-14)

What `github.com/tarmoj/radio1965` is, end to end: the app, the server, the
content sources, the media path and the push path. Read from the source at
commit `0796bf6` (v0.5.7, 2026-09-12, 112 files, ~5,651 source lines) and
measured against the live deployment on 2026-09-14.

⚠️ **Three labels are used throughout and they are not interchangeable.**
**READ** = it is in the source. **MEASURED** = I asked the running system and
this is what it said, with the time. **INFERRED** = neither; reasoning, and
flagged as such. Companion to `uuu-integration-2026-09.md`, which measures the
stream from positron's side; this one is about their side of it.

🔴 **It is NOT the archival platform.** Every "1965" in this repo is a NAME —
an Icecast mount, an API path, a service title. There is no 1965 material, no
historical metadata and no date model reaching earlier than now. That was
established on 2026-09-04 and is repeated here because the repo's name invites
the mistake every time somebody new reads it. The archival platform of the
same name is a set of theses; this is a content-forwarding app for the
**Estonian Centre of Contemporary Music** (eccm.ee).

## 2. Where the content comes from

READ, and confirmed by MEASURING the live API (8 events, 2026-09-14):

| source | how it arrives | share of the live 8 |
|---|---|---|
| a person, via the editor form | `POST /events/publish` | 7 |
| **eccm.ee Joomla** | polled, §3 | 1 |
| the broadcast itself | `icecast_on_connect.sh` | 1 (`livestream`) |

Almost nothing is hosted by them: the events carry **URLs to other people's
sites** — `sirp.ee`, `ubuweb.com` (a Cage/Feldman conversation), `uuu.ee` files,
an `eccm.ee` article. **Five of the eight are test entries** ("Veebilink test",
"Video test", "Audio test").

Event types, READ from `db.py:33`:
`text · audio · video · audiostream · videostream · article · webcontent · livestream`

The time model is two columns and a sweep: `publish_at` (when it appears and
notifies) and `shelf_at` (when it moves from New Arrivals to the Collection).
Status is `unpublished → new → shelved → archived`. ⚠️ Their "Archive" is a
VISIBILITY FLAG, not a historical archive.

## 3. The Joomla path — a poll, not a webhook

🔴 **There is no webhook, and their own documentation does not know that.**
`project-description.md:195` still lists it as open — *"maybe Joomla import is
poll-based (cron) or event-based (a small Joomla plugin fires a webhook on
article publish/update)"* — and the diagram at :135 hedges *"polls/receives
webhook"*. The code settles it: **poll**.

READ, `server/joomla_importer.py`:

    JOOMLA_BASE_URL   = "https://eccm.ee/api/index.php/v1"   # Joomla Web Services API
    JOOMLA_CATEGORY_ID = 47                                   # one category
    HEADERS = { Authorization: Bearer $JOOMLA_API_TOKEN,
                Accept: application/vnd.api+json }            # JSON:API

    GET /content/articles
        filter[state]=1              # published only
        filter[category]=47
        list[fullordering]=a.modified DESC
        list[limit]=100

Cadence, READ from the crontab lines in the files themselves:

    */5 * * * *   cron_joomla_import    → upsert as status="unpublished"
      * * * * *   cron_publish          → send FCM, status="new"

So **worst case from pressing publish in Joomla to a phone buzzing is ~6
minutes** (INFERRED from those two periods).

Four details worth keeping:

- **Incremental.** A local `last_sync` file means it only asks for articles
  modified since the previous run. Gitignored — runtime state, not a secret.
- **Idempotent.** An article already imported has only title/summary/url
  refreshed; `status`/`publish_at`/`shelf_at` are left alone and **no
  notification is re-sent**.
- **It re-checks the server's own filter.** `joomla_importer.py:111` — *"Don't
  trust the server-side filter alone - Joomla's API has had bugs where combined
  filter[] params silently drop one another."* That is this repo's own "check
  the instrument" rule, arrived at independently.
- **The app never holds the Joomla token.** `GET /articles/{id}` on THEIR server
  proxies Joomla, wraps the bare HTML fragment in a responsive template and
  rewrites relative `src`/`href` (`images/foo.jpg`) against the site root. Good
  token custody.

MEASURED 2026-09-14: `eccm.ee` is Joomla (`generator: Joomla! - Open Source
Content Management`, redirects to `/index.php/et/`), and its API correctly
answers **401 Forbidden** unauthenticated. ⚠️ Note the contrast with §8.

## 4. The push path

It is the point of the product — the server is literally
`FastAPI(title="Radio 1965 Notification Service")`.

READ: `notifications.py` sends through **FCM**, which fans out to **APNs** for
iOS, in one codepath, with dead-token pruning. Native receivers: Android
`FirebaseMessagingService` + JNI; iOS `FIRMessagingDelegate`. There is also a
real **service worker with Web Push and a VAPID key**.

⚠️ **It is not a PWA.** No web manifest anywhere, and the service worker has no
fetch handler and does no caching. `client/` is a 114-line debug harness.

🔴 **The trap they hit, documented with its reasoning** — `main.py:221-239`.
Ending a broadcast sets status `archived`, **not** back to `unpublished`,
because `cron_publish.py` sweeps every `unpublished` row whose `publish_at` has
passed. Setting it back made the very next cron tick treat the just-ended
broadcast as newly due and **re-send the "is on air" push**. A retraction that
resurrects itself, once a minute.

**This is the most transferable thing in the repo.** Any positron flow with "a
live thing ended, take the card down" plus a time-based sweep has it latent.
Their other discipline worth taking: **a push is FYI-only and never a data
source** — it triggers a re-fetch, it never mutates the model.

## 5. The media path

READ + MEASURED 2026-09-14T10:48 UTC, direct against `live.uuu.ee:8001`:

| | |
|---|---|
| server | Icecast 2.4.4, up since 2026-09-11 06:43 +0300 |
| mount | `/radio1965` — `icy-name: Radio 1965`, `icy-description: Improvisations by EMA`, genre Avant-garde |
| format | MP3, **128 kbit/s, 44.1 kHz, stereo**, `icy-metaint: 16000` |
| stream start | 2026-09-11T19:19:59 +0300 |
| listeners | 2, peak 2 |
| sound | **mean -20.4 dB, max -1.0 dB** against a synthesised-silence control at **-91.0 dB** |
| what it is | **a shuffled/looping playlist of pre-recorded files** — titles advance non-sequentially (`01_EMA_Improvisation_I`, `07_…_II`, `05_…_IV`). Not a live mic; not a clock-driven simulation (there is no schedule anywhere in the repo). |

The `livestream` event's `publish_at` matches Icecast's `stream_start` to **two
seconds**, which is `icecast_on_connect.sh` firing — so the on-air banner is
evidence of the mount, not a claim beside it.

🔴 **Two things make that stream unreachable from a browser**, and they are why
positron's `/radio1965/` exists at all:

1. **No TLS.** It is `http://…:8001`. A page served over HTTPS may not load it —
   the browser refuses the mixed-content fetch *before* any CORS question.
2. **No CORS.** Even over plain http, `createMediaElementSource` on a
   cross-origin element with no permission header yields a graph that outputs
   **silence** while the speakers play normally.

positron's `shout` worker re-serves the mount with TLS and
`access-control-allow-origin: *`, which is the whole of what `/radio1965/`
needed. MEASURED through it: 200, `icy-name` preserved, TTFB 300 ms.

⚠️ **A caution about probing them.** On 2026-09-14 two separate attempts to
reach port 8001 failed instantly and a `portquiz.net:8001` control failed in the
same moment — which made a transient look like a systemic block, and produced a
confident wrong conclusion ("the port is blocked"). It is not: `nc` and `curl`
both reach it. **Two failures agreeing is not proof when they can share a
cause.**

Also present but unverified: nginx-rtmp and an HLS endpoint on `:4443`
(`/hls/<key>.m3u8`), CORS-open per the companion document.

## 6. How the UI is implemented

**Qt 6 / QML, compiled native, iOS + Android** — package `org.eccm.vain`, app
name **"Väin"**. READ from `CMakeLists.txt`: `Qt6 Quick Network Multimedia
WebView`, `qt_add_qml_module`, `qt_add_resources` (a `qrc:/images/` bundle), and
`qt_add_ios_ffmpeg_libraries` for the iOS build.

The QML tree, by size:

| file | lines | what it is |
|---|---|---|
| `Main.qml` | 405 | `ApplicationWindow` → `ToolBar` header, `Drawer` menu, `StackView`, and a `TabBar` + `SwipeView` pair |
| `PlaybackController.qml` | 242 | the playback state machine |
| `PlayerBar.qml` | 204 | the persistent player strip |
| `CollectionPage.qml` | 203 | the shelved items |
| `BroadcastPage.qml` | 194 | contributor broadcasting |
| `Box.qml` | 178 | the card container |
| `EventDelegate.qml` | 158 | one event, as a card |
| `Shelf.qml` | 154 | a shelf of cards |
| `WebViewPage.qml` | 105 | in-app browser (Qt WebView) for articles |
| `SearchResultsPage.qml` | 104 | search |

**The metaphor is a library.** Two tabs, **icon-only** — `home.svg` (New
Arrivals) and `cards_stack.svg` (Collection); their text labels are present but
commented out in `Main.qml:347-348`. Items are cards on shelves; tapping an
article opens a WebView rather than leaving the app; a player bar persists
across navigation.

The Drawer carries *Something*, *Info*, *Become a Contributor* and *Leave
contributor role*. Contributor access is a **password gate in the client**
(`Main.qml:262-269`, "Incorrect password." / "Submit"), which is a client-side
check, not an authorisation boundary.

C++ beneath the QML: `icecastbroadcaster.cpp` (335 lines — captures from the
phone, encodes MP3 with LAME, sends to an Icecast mount),
`notificationmanager.cpp` (213), `eventsapiclient.cpp` (73).

## 7. Is it "vibecoded"? No.

Asked directly, so answered directly. 52 commits, **one human author**, no AI
tool dotfiles, zero AI-attributed commits. Commit messages read like a person
at speed — `gitignroe`, `Fixed Aoo Stire requirements`, `Initial steam storing
plan`, `Shorten joomla arcicle summary`. The decisive evidence is §4's
docstring: it documents a **production burn** ("caused the very next cron tick
to … resend"), cross-referenced to their own spec. A generator does not know
that; somebody who got woken by it does. The defects fit a solo developer
shipping fast — no tests, no auth, a schema/`db.py` enum divergence — not
generated scaffolding, which usually *has* the test file and the auth stub.
Some AI assistance in the prose is plausible; "generated wholesale" is not.

## 8. 🔴 Two things to tell them, privately and soon

1. **`POST /events/publish` is unauthenticated on the public deployment.** It
   answers 422 (validation), not 401 — verified non-destructively; the probe
   deliberately did NOT publish, because that would have fired a live push to
   every subscriber. Alongside it: `allow_origins=["*"]` against the code's own
   *"restrict before production"* comment, a public editor form, public `/docs`,
   and an Apache autoindex exposing `editor_old/`. **Anyone can push a
   notification to every installed app.** Note their Joomla API gets this right
   (401); it is only their own API that is open.
2. **The Icecast source password is committed in plaintext**, in two files. Not
   reproduced here. Already raised as item 13 of `uuu-integration-2026-09.md`;
   repeated because it and (1) point the same way.

**And there is no LICENCE at all** (GitHub reports `license: null`). positron
may READ this repo; it may not copy code from it without asking.

## 9. What positron should take, and what it should not

**Take:** the archived-vs-unpublished trap (§4) as a rule about sweeps; the
push-is-FYI-only discipline; occupancy-as-UI-state from `status-json.xsl`,
which maps onto the relay's existing `/room/<name>/stats`.

**Do not take:** the Qt stack, MySQL + cron, and above all the auth model.

**Where positron is ahead, with this repo as the evidence.** Their deployed
server was running 7-day shelf defaults **13 days after the commit that changed
them to 1 day** — provable only by inferring a deploy date from the shape of
production data, because nothing reports which build is live. That is precisely
the archaeology `BUILD <sha>-<hhmmss>-<tree>` makes unnecessary. Likewise
`sql/schema.sql` and `server/db.py` **silently diverged on the event-type enum**
(production runs `livestream`; the DDL would reject it) with a comment still
asserting they match. Zero tests, zero CI.

**One genuinely new angle on an existing rule.** CLAUDE.md frames *"a fixed port
is a shared mutable global"* as a collision risk. This adds a sharper cost: **a
non-standard port is unreachable for some fraction of real listeners.** Their
stream is healthy and still could not be heard from two different networks
without a relay in front of it.
